# ADR 0013: Token guards, the egress seam and the loopback secret

- Status: Accepted
- Date: 2026-11-16
- Issue: #224
- Owner: security-lead (implemented by impl-224)

## Context

Issue #224 asks for shared guards for the token isolation rules of section 4.6 (ARC-6, ARC-7, AT-17, COL-78). Issue #207 (PR #256, `crates/http-policy`) owns the host allowlist, the redirect policy and the non-JSON page rule. PR #256 is not merged when this ADR is written. Issue #25 owns `config_write`, #36 owns the gateway hardening and #176 owns the C ABI. The issue left the points below open.

## Decisions

1. **Rules 2, 3 and 6 are a seam, not a second policy.** `mog_core::egress_policy::TokenEgressPolicy` is the trait that R7 and R8 call. `contract_violations` is a contract suite of fake hosts and pages. Tests prove that the suite fails an allow-all policy and a deny-all policy. When #256 merges, an adapter over `http_policy::TokenPolicy` implements the trait and a test asserts zero violations (`TODO(#207)`).
2. **The scrubber is hand-written.** `mog_core::token_guard` matches the 7 patterns of rule 7 with no regex crate. `\w` is ASCII (`[A-Za-z0-9_]`). A match is redacted to the end of the secret: the whole JWT, the `dapi` hex and an optional `-<digits>` suffix, the full PEM block up to its `-----END ...-----` line (or the end of the text), and the `password=` value up to white space, `&`, `;`, `,` or a quote. `password=` matches in any ASCII case. `ghp_…` is `ghp_` and one or more ASCII letters or digits. The patterns are the requirement text, so `dose` followed by a hex digit also matches English words such as "dosed". We accept this over-redaction. The scan is linear in the input length: a failed `eyJ` run is not scanned again (test `arc_6_rule_7_scrub_is_linear_on_hostile_input`). `scrub_json` keeps both values when two keys scrub to the same text (`[REDACTED]`, `[REDACTED]#2`).
3. **Rule 5 strips at every depth.** `strip_profile_keys` removes every key equal to `profile` in any ASCII case, in nested objects and arrays too. R8 forwards only `mcp_transport::forwardable_tool_args`.
4. **MB-02 key names.** `check_config_json` splits each key into words at non-alphanumeric characters, at lower-to-upper case changes, at letter-digit changes and before the last capital of an acronym. It rejects the key if a word is `token`, `password`, `passwd`, `secret` or `pat`. It also joins the key in lower case and rejects it if that holds `password`, `passwd`, `secret`, or `token` not followed by `s`. So `accessToken`, `accesstoken`, `APIToken`, `PATValue`, `password1` and `github_pat` fail, and `maxTokens`, `path` and `patterns` pass. `pat` is checked only as a word, because `path` and `patterns` hold it. The check is a name rule, not a full secret classifier: it also rejects `tokenizer`, `tokenBudget` and `secretary`, and it accepts `apiKey`, `privateKey` and `credential` (MB-02 names only token, password, secret and pat). Values of those keys are still checked against the rule-7 patterns. A key or value that matches a rule-7 pattern also fails. The error is a content-free code. The call in `ipc::handle` stays `TODO(#25)` (contract file).
5. **One secret per session, as a bearer header.** `LoopbackSession` binds three listeners on `127.0.0.1` with OS-chosen ports. It makes one 256-bit secret from the OS RNG (`getrandom`), as 64 lowercase hex characters. Lowercase hex cannot contain a rule-7 pattern. Each request must have exactly one `Host` of `127.0.0.1:<port>` or `localhost:<port>` (403 otherwise, a DNS rebinding guard). It must also have exactly one `Authorization: Bearer <secret>` (401 otherwise, constant-time compare). The handler runs only after both checks. Reply bodies go through `scrub_json`. Each endpoint has at most 32 open connections; further connections to it close at once, so a full endpoint does not lock out the others. A local process can still fill one endpoint before auth, for 5 s at a time; SP-19 sets the final limits (`TODO(#111)`). The whole request must arrive in 5 s (408 otherwise). `close` stops the listeners, shuts down every open connection and joins every connection thread, and `close` returns only after every handler has returned. A handler that has already started when `close` begins runs to its end; the real handlers (#113, #139) must check their own closed state if they do long work. A handler panic frees the connection and the caller gets 500. The secret bytes are zeroed on drop. `HarnessConfig` redacts the secret in `Debug`.
6. **Wire details wait for SP-19.** The skeleton speaks HTTP/1.1 with a `Content-Length` body (digits only), one request per connection. It rejects chunked bodies. `close` waits for running handlers with no time limit, so the real handlers must time out their upstream calls. MCP streamable HTTP and SSE, the paths and how the harness sends the header are `TODO(#111)`. The real handlers are `TODO(#113)` (`bottle-mcp`, model proxy) and `TODO(#139)` (Genie One MCP proxy).

## Notes

- `ipc::IpcError::UnknownCommand` holds the command name. The Tauri host never sends it, because it returns `false` for a name that is not in `COMMANDS`. The C ABI (#176) must send only error codes, or call `ScrubbingGateway` and `token_guard::scrub`.
- Rule 1 names only the v1 `custom_agent` URL as an exception. The 4.5 table also lists `profile_login {workspaceUrl}`, the value for `databricks auth login --host`. It is not a request target, so the rule-1 test allows it. This difference is posted on #224.
- The rule-4 Rive test fails any file under `src/` that uses the Rive runtime and does not set `enableRiveAssetCDN: false`. No Rive code exists in `src/` yet.
- `ScrubbingGateway` wraps any R12 gateway. The hardened gateway (#36) and the C ABI (#176) use it.
- Rule 8 (Lakebase, v1) has only a check that the `lakebase` feature is off by default. The host rule is `TODO(#193)`.
