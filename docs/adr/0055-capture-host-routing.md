# ADR 0055: Capture routing on the host and the cap timer

- Status: Accepted
- Date: 2026-11-16
- Issue: #425 (contract change, for #4, #14, #21, #22, #23)
- Owner: contract-lead (implemented by impl-425)

## Context

R2 `CaptureCore` (#273) is on main, and `mog_core::ipc` has rows for the `capture_*` commands. The Tauri host did not route them: they answered `not_implemented`. PR #392 (#279, ADR 0039) added `capture_resume` and left a TODO marker for #425 on its route. The host also had no timer that calls `CaptureService::tick()`, so the 120 s hold cap (CAP-04a) and the 5 min hands-free cap (CAP-04b) never fired. The issue left these points open: the code when no service is managed, the event for a stop, the thread of `capture_start`, the reply of `capture_start`, sessions, and `capture_subscribe`.

## Decisions

1. **One host per process.** `src-tauri/src/capture_host.rs` has `CaptureHost`. It answers the seven commands `capture_start`, `capture_stop`, `capture_pause`, `capture_resume`, `capture_status`, `capture_stop_all` and `capture_subscribe`. It owns the one `CaptureCore`, the owner MOG of each lease and the cap timer. The app builds it in `setup` and manages it. `route_from` reads it with `try_state`. If no host is managed, each `capture_*` command answers `host_failed`. This is the existing code for a missing host part (ADR 0040, decision 3), so no new code is added.
2. **Errors.** R2 errors map with `CaptureError::to_ipc(command)`: `mic_busy`, `unknown_lease`, `invalid_mode`. A device fault is `host_failed`. `capture_stop`, `capture_pause` and `capture_resume` compare the lease owner with `mogId`. A mismatch, a lease that R2 never issued, a non-canonical lease (`007`) and a released lease all answer `unknown_lease` (ADR 0007, decision 2).
3. **Lease owners.** The host records the owner when `start` returns a lease. The event sink removes the owner when the lease stops. A stop can come before the record (a `stop_all` or a cap on another thread). The host then keeps the lease number in a `gone` set, and the record does nothing.
4. **The `capture_start` reply.** The reply is the capture state after the grant. Its `leaseId` is always the new lease. For a PTT directed into a session, the session lease owns the mic, so `capture_status` shows the session lease. The caller still needs its own lease to stop it. If a cap or `stop_all` ends the new lease before the reply is built, the reply has the new `leaseId` with `recording: false`. A later `capture_stop` then answers `unknown_lease`.
5. **Sessions fail closed.** `capture_start` with `mode: "session"` answers `consent_required` until #65 checks the consent token of `session_attest`. `policy` goes to R3 SessionGuard (#67) then. `TODO(#65)`.
6. **A new event `capture.stopped`.** The Tauri name is `capture:stopped`. It is a core-to-brain event on the brain Channel. Its payload is `CaptureStopped {leaseId, mogId, mode, reason}`. `reason` is one of `manual`, `hold_cap`, `hands_free_cap`, `preempted`, `panic`, `device_lost`, and the five reasons of the #14 lifecycle (ADR 0057): `released`, `discarded`, `tap`, `escape`, `vad_end`, and `zero_buffers` of #22. A test checks that each R2 `StopReason` code is the same on the wire. `capture.state` alone cannot tell the brain why a capture ended, for example the hold cap. The event is not in the 4.5 list of the requirements, like `mog.level` (ADR 0040, decision 11). `capture.state` carries `CaptureState`. Both payloads are content-free (CAP-01b). `BrainChannel::send` scrubs them (SEC-01).
   Three threads can send these events: the IPC thread, the worker of `capture_start` or `capture_resume`, and the cap timer. The core sends events after it releases its lock. So two `capture:state` events can reach the brain in a different order from the order of the decisions. An example is a cap tick that sends "idle" while a new start sends "recording". The brain must treat the reply of each `capture_*` command and of `capture_status` as the truth. It must treat `capture:state` only as a hint. A sequence number is possible in a later contract change.
7. **`capture_start` and `capture_resume` run on a worker.** They open the audio device, and a CoreAudio or WASAPI open can be slow. So they run on `spawn_blocking`, like the R11 ops (ADR 0022, decision 6). The other `capture_*` commands run inline. They never wait for the device, so the panic stop stays fast (MB-05). The brain must await `capture_start` before it sends `capture_stop` for that lease. It needs the lease ID first anyway. MB-05 is covered here only on the command path (`capture_stop_all`). The panic key that calls `stop_all` in Rust with no TS is #66.
   A worker can run later than an inline call that arrived after it. So the IPC handler takes an admission ticket (`CaptureTicket`) for each capture call before `schedule`, in arrival order. The ticket holds a panic number and a pause number. `capture_stop_all` and `shutdown` bump the panic number. Each `capture_pause` bumps the pause number and records it on its lease. A queued start checks the panic number before it calls R2. If the number moved, the start answers `unknown_lease`, and the mic never opens. This is the same answer that R2 gives for a start that `stop_all` cancels while the device opens. The start checks again after R2 grants the lease, for a `stop_all` that came during the open. It then stops the new lease, and the brain sees a `capture.stopped` event with the reason `manual`. A queued resume checks the panic number and the pause number of its own lease, before and after R2. If a later pause of that lease came first, the host pauses the session again and answers the paused state, because the user's pause wins (CAP-13b). The brain must read `recording` in the resume reply. A stop of the lease needs no number: R2 then answers `unknown_lease` to the resume. A pause or stop of another lease does not affect a resume. After `shutdown`, a start answers `host_failed`. The IPC handler takes the ticket with `ipc::admit`, which a test checks. `TODO(#65)`: no session can start yet, so the resume branch is checked only at the ticket.
8. **The cap timer.** `CapTimer` is one thread. It waits on a condition variable until the armed deadline, in monotonic ms of the shared clock (#229). With no deadline it waits until an arm. So it never busy-loops. At the deadline it calls `tick()` and arms the deadline that `tick()` returns. After each grant and each resume, the host calls `tick()` and arms its result. A session has no cap deadline today, so the arm after a resume has no effect yet (`TODO(#65)`: test it once a session can start). The #14 lifecycle (ADR 0057) adds two more deadlines: the post-roll after `release` and the VAD end after `voice_activity`. The host does not call these yet. `capture_stop` is a plain stop until #433 adds its `end` argument, and the VAD is #116. When the host calls them, it must arm the timer with `tick()` in the same way (`TODO(#433)`, `TODO(#116)`). `arm` only moves the deadline earlier, and it wakes the thread. Before each `tick()`, the thread clears the deadline. After `tick()`, it keeps the earlier of the result and any arm that came meanwhile. So an arm that races a tick is never lost. A stale early deadline costs only one extra `tick()`. `CapTimer::settle` wakes the thread and returns when it waits again. Tests call it after they move `SimClock`, so the caps fire with no real sleep. `CapTimer::last_wait` reports the last wait: `For(d)` with `d` the time left to the deadline, or `Forever`. A test checks it, so no real sleep is needed to prove that the thread does not spin. If `tick()` panics (for example in an event sink), the thread catches the panic and tries again after `TICK_RETRY_MS` (1 s). The core commits its state before it sends events, so the retry is safe, and the caps never stop for good.
9. **The mic backend.** On macOS and Windows, the app builds the host on the cpal `MicDevice` of #388 (ADR 0038). It connects the `FailureLink`, so a stream that fails after it opened stops its leases. The frames go to the level stream and to the RAM-only PTT buffer (#21, ADR 0078). If the mic thread cannot start, or on other platforms (the Linux CI build), the app uses `UnwiredMic`, so the app still runs. Each open fails with the device code `no_device`, so `capture_start` answers `host_failed` and no lease is granted.
10. **Quit.** On `RunEvent::Exit` the app calls `CaptureHost::shutdown`. It stops every lease (the mic closes) and joins the timer thread.

## Consequences

- PTT and hands-free capture work end to end through IPC on macOS and Windows. The captured frames reach STT once #21 adds the PTT buffer. #14, #21, #22 and #23 can use the real route.
- `capture_resume` (#279, PR #392) routes to `CaptureService::resume`, and the open item of ADR 0039 for #425 is closed. A resume needs a paused session, and no session starts before #65. So today a resume answers `invalid_mode` for a live PTT or hands-free lease.
- `capture_subscribe` checks its two Channels and answers `{}`. Amended by #476 (ADR 0067, decision 7): the host sends the mic level on `onLevel`. `TODO(#514)`: the partial text of R4 feeds `onPartial`.
