## 2. Method

1. **Tauri app** (`spikes/sp-01/`, its own `[workspace]`). It has one window, `mog-spike`, 240x240 and 20 px in from the bottom-right corner. The config has `transparent: true`, `decorations: false`, `alwaysOnTop: true`, `focus: false`, `shadow: false` and `skipTaskbar: true`, and no `macOSPrivateApi`. At setup the app calls `set_focusable(false)` and sets the activation policy. Then it runs the overlay step: clear background, not opaque, `canJoinAllSpaces | fullScreenAuxiliary | stationary`, `acceptsMouseMovedEvents`, and `orderFrontRegardless`. Env switches (`src-tauri/src/main.rs`, `src-tauri/src/macos.rs`):
   - `SP01_POLICY` = `accessory` | `prohibited` | `regular`.
   - `SP01_AIOA` = `1` | `0` sets `tauri::Builder::activate_ignoring_other_apps`. The tao default is `true`, and tao calls `activateIgnoringOtherApps` at launch (`tao-0.37.2/src/platform_impl/macos/app_state.rs:290-292`).
   - `SP01_TRACK=1` adds an `.activeAlways | .mouseMoved | .mouseEnteredAndExited | .inVisibleRect` NSTrackingArea on the content view. Its owner is an objc2 `NSResponder` subclass (`define_class!`, selectors `mouseMoved:`, `mouseEntered:` and `mouseExited:`). The owner logs each native call and forwards it to the page as a synthetic `PointerEvent` (`isTrusted=false`).
   - `SP01_PANEL_SWAP=1` swaps the window class to an `NSPanel` subclass (`canBecomeKeyWindow` = false) and adds `NSWindowStyleMaskNonactivatingPanel`. This is the same mechanism that `tauri-nspanel` 2.1.1 uses.
   - `SP01_KEY=1` together with `SP01_FOCUSABLE=1` builds the key-window control.
   - `SP01_SNAP` takes a WKWebView `takeSnapshot` of the Tauri webview.
2. **CSP** is exactly ARC-4. Rive cannot `fetch` its wasm under this CSP, so the page gets the wasm and the `.riv` as bytes over IPC (`RuntimeLoader.setWasmBinary`, `buffer:`). `enableRiveAssetCDN: false`.
3. **Page** (`web/`). It loads ONE runtime per run (`@rive-app/webgl2` or `@rive-app/canvas`, 2.50.0) and lists the state machines, inputs and view-model properties. If `mood` and `level` exist, it cycles 7 moods and the level; otherwise it loops the timeline animations. It logs `pointermove`, `pointerenter` and `mouseover` (capture phase) with `isTrusted`, and logs the `requestAnimationFrame` count and `visibilityState` every 5 s. Rust adds its receive time and the window occlusion state.
4. **Hover poster** (`probe-swift/PostMoves.swift`) posts `CGEvent` mouse moves at the HID tap into the window rect: 2 bursts of 100 moves at 10 ms per case. `AXIsProcessTrusted()` was `true`.
5. **Probe** (`probe-swift/Probe.swift`, not Tauri). It is a borderless `.nonactivatingPanel` with a WKWebView (`drawsBackground=false`), the same page and the same CSP. `SP01_TRACK=1` adds a tracking area owned by the WKWebView. `SP01_TRACK=2` adds a tracking area owned by an `NSResponder` subclass with `override` methods. `SP01_SELFTEST=1` checks the selectors.
6. **Scripts.** `run_activation_offscreen.sh` runs the activation matrix with the window at x=-3000. `run_measurements.sh` runs the whole on-screen matrix ONCE and closes each window when its case ends. CPU and memory come from `top -l 31 -s 1` over the app PID plus the WebKit PIDs that the launch made; the first sample is dropped.
7. **Analysis** (`measure/sp01_measure.py`) computes CIEDE2000 (checked against the Sharma 2005 pairs), transparency over non-sprite pixels, halo, white flash, hover ratio, hover breakdown (native / trusted / synthetic) and the `top` sums.

## 6. Findings

1. **WebKit does not deliver mouse moves to the page in a non-key window.** This held for both runtimes, in Tauri and in the probe, as a window and as an NSPanel (0 of 200 each). Some trusted `pointerenter` and `mouseover` events do arrive at entry. A tracking area owned by the WKWebView does not help (probe `TRACK=1`: 0).
2. **An objc2 `.activeAlways` tracking area on the Tauri content view fixes hover.** Its owner is an NSResponder subclass that forwards into the page. It got 198 of 200 moves as host-forwarded DOM `PointerEvent`s while the window was not key and the app was not active. The page events are synthetic (`isTrusted=false`), so the view must not filter on `isTrusted`. This is the "own objc2 fix" step of the fallback chain, and it worked.
3. **A real NSPanel alone does not fix hover.** The Tauri NSPanel class swap with `nonactivatingPanel` got 0 of 200. With the tracking area added it got 198 of 200. The panel is still useful for ARC-3 (a `card-<id>` key-capable non-activating window), but hover depends on the tracking area. `tauri-nspanel` 2.1.1 (in the requirements stack) does the same two things: a panel class swap, and a `tracking_area` builder whose generated class implements `mouseMoved:` (`src/builder.rs:278`, `src/event.rs:165`). It was not added as a dependency here.
4. **Activation: `activate_ignoring_other_apps(false)` is the fix.** With it, Accessory, Prohibited, Regular and `LSUIElement` launches never changed the frontmost app (all 2/2 offscreen, and 7/7 non-control Tauri cases on-screen in run4). With the tao default (`true`), the Accessory policy and `LSUIElement` both activated the app. Prohibited stayed inactive either way.
5. **`macOSPrivateApi` is a no-op in this Tauri version, and the private API is used anyway.** `tauri-2.12.5/src/lib.rs` says the feature is "**No-op since Tauri 2.12.1** because the APIs are always enabled now". `wry-0.57.2/src/wkwebview/mod.rs:416` always sets the private KVC key `drawsBackground=false` when the window is transparent, and the probe uses the same key. So the NFR-14b text check (no flag in the config) passes trivially. Its intent (no private API, the MAS path in D32/COL-36) does not hold for any transparent Tauri 2.12.5 window. Fallback step 3 (`macOSPrivateApi: true`) cannot change anything on this version. **NFR-14b and COL-36 need an owner decision.**
6. **The ARC-4 CSP blocks Rive's default wasm `fetch`.** The app must pass the wasm and `.riv` bytes over IPC, or ARC-4 must allow `connect-src 'self'`. The spike uses IPC bytes for both runtimes.
7. **Offscreen windows do not render** (0 rAF frames). Tauri `takeSnapshot` did not complete offscreen but did complete on-screen. Offscreen numbers are valid for alpha and activation only.

## 7. Recommendation

**Runtime: provisional `@rive-app/canvas`** (NFR-16a). Confirm it with the MOG mascot in the signed rerun.
- Animating (run4): canvas 11.1 % CPU / 365.6 MB against webgl2 13.8 % / 383.2 MB. Idle: canvas 2.8-3.0 % / 111.7 MB against webgl2 3.8 % / 130.3 MB (run2; the run4 webgl2 idle sample is invalid).
- webgl2 had the only render stall (run2, about 34 s). Transparency does not decide the runtime: both runtimes give the same alpha.

**Hover (UX-08a):** use an objc2 `.activeAlways` tracking area on each `mog-<id>` window, with an NSResponder owner that forwards into the view (or the `tauri-nspanel` tracking area). The view must accept host-forwarded `PointerEvent`s. This changes the UX-08a acceptance rule from "DOM pointer events" to "DOM pointer events, forwarded by the host when the window is not key". Rows to flag: UX-08a, COL-71.

**Activation (ARC-3):** `tauri::Builder::activate_ignoring_other_apps(false)` plus the Accessory policy and `set_focusable(false)`. Use an NSPanel (class swap or `tauri-nspanel`) for `card-<id>`.

**`macOSPrivateApi` needed: not decidable as worded.** The flag is a no-op on Tauri >= 2.12.1, and the private `drawsBackground` key is always in use. This needs an owner decision on NFR-14b and COL-36.

**Fallback chain reached:**
1. canvas runtime: tried; same hover and alpha as webgl2.
2. Own objc2 fix: tried and **works** for hover (tracking area). Activation is fixed by the Tauri builder option.
3. `macOSPrivateApi: true`: not applicable (a no-op on 2.12.5).
4. Static WebP poster: not needed.
