Start here: Motherbricks on one page

Product: Motherbricks is the desktop app. Each MOG is a floating agent with its own backend, workspace, hotkey and memory scope.

The complete MVP path. Local memory handles recall. Lakebase is optional durable storage. Every backend request uses the selected workspace and an explicit route.

1. Hold key→2. Transcribe→3. Clean with raw fallback→4. Choose Dictate, Ask or Save→5. Insert text or show Genie blurb

MVP includes

  • Tauri desktop app with multiple MOGs
  • Push-to-talk and local STT
  • Bounded cleanup with raw restore
  • Genie One MCP through CLI profiles
  • Local encrypted memory and recall
  • Optional Lakebase durable sync

Non-negotiable guardrails

  • No silent or ambient recording
  • Exact context and target approval
  • One owner for each audio source
  • Workspace-pinned conversations
  • Tokens remain in the native core
  • No duplicate ask after uncertain delivery

Later and still to prove

  • v1: meetings, hands-free and hosted ASR
  • v2: custom agents and companions
  • Run macOS and Windows device spikes
  • Run a live Databricks workspace test
  • Measure STT and recall on reference hardware
  • Complete security, accessibility and legal gates

Default interpretation: “Always available” means that a running MOG can receive an explicit command. It does not mean continuous recording. The sections below contain the complete requirements and acceptance evidence.

1. Executive rundown

The baseline uses local-first voice interaction, explicit backend routing and workspace-bound identity. The app must never turn availability into silent capture.

Desktop shell

Use Tauri v2, React, TypeScript and a native Rust core for the MVP. Test the Tauri hotkey plugin before selecting a custom hook.

Capture

Use push-to-talk by default. Require trusted native confirmation for hands-free dictation and meetings. Keep a separate native recording indicator.

Speech

Use local STT for offline dictation. Parakeet with sherpa-onnx is the leading candidate. Keep hosted ASR behind capability and policy checks.

Cleanup

Preserve raw and cleaned text. Use a two-second cleanup deadline. Return raw text on failure. Never overwrite inserted text late.

Genie

Use Genie One MCP by default. Ask, poll serially, retrieve results when needed and request cancellation when supported.

Context

Keep context sharing off by default. Include approved context in the next question string. Show the exact payload and target before sending.

Workspaces

Reuse OAuth U2M Databricks CLI profiles. Keep active conversations and meetings pinned to their starting workspace and backend.

Memory

Use an encrypted local store for interactive recall. Use a Motherbricks-owned Lakebase schema for durable sync when configured.

Meetings

Do not stop at 60 minutes. Use manual and environmental stops, a 90-minute review and a four-hour hard ceiling.

Security

Keep tokens and credentials in the native core. Treat transcripts, memory and backend content as untrusted data.

Many MOGs

Use one Audio Broker. Give one MOG ownership of an audio source. Reject conflicts visibly without hidden queues.

Verification

Physical macOS/Windows spikes and live workspace tests remain release gates. This document does not claim that those tests passed.

Release status: the requirements are integrated. Implementation feasibility is not yet certified. The unrun device, latency and live-service gates are listed in Section 14.

2. Scope and controlled glossary

2.1 Product boundary

  • Motherbricks runs locally on macOS and Windows for the MVP.
  • Motherbricks creates and manages one or more MOGs.
  • A MOG can dictate text without a Databricks request.
  • A MOG can send an explicit question to its selected backend.
  • A MOG can save approved context locally and recall it later.
  • A MOG can synchronize approved memory to Lakebase when configured.
  • A MOG can show a short response blurb and a safe link to Databricks.

2.2 Non-goals for the MVP

  • Continuous ambient recording without an explicit user action.
  • Automatic submission of every detected meeting question.
  • Mobile or web parity for global hotkeys, system audio or paste into another app.
  • A single universal API for Genie, Databricks Apps and Model Serving agents.
  • Automatic Lakebase Search enablement or managed Agent Memory as the system of record.
  • Verified speaker identity from the You and Others track labels.
  • A guarantee of Genie answer latency, remote deletion or backup erasure.

4. System architecture

The native core owns privileged operations. The webview presents state through restricted IPC. Provider interfaces keep the UI replaceable.

Figure 1. Motherbricks system context. Solid trust boundaries separate the webview, native core, CLI and Databricks services. Alternate backends are separate adapters.

4.1 Architecture rules

  • One native Audio Broker owns global input and audio resources.
  • One Credential Broker binds credentials to approved origins.
  • One BackendAdapter contract exposes explicit capabilities.
  • One MemoryStore owns local recall and durable synchronization.
  • Each cloud request uses the selected workspace and approved payload.

5. Voice-to-answer sequence

Dictation and backend questions use different routes. Memory recall is local. Context-bearing submission requires exact approval.

Figure 2. Push-to-talk, local recall, approved context, Genie polling and blurb projection. Lakebase synchronization is asynchronous and is not the interactive recall path.

Delivery rule: a transport failure after possible acceptance creates an uncertain state. Motherbricks must not repeat the question automatically. It must resume or reconcile the original response when IDs exist.

6. MOG and capture states

The MOG lifecycle, interaction presentation and capture authority are related but separate. A sleeping mascot cannot disable the native recording indicator.

Figure 3. MOG lifecycle, capture states and resource arbitration. Calendar end and 90 minutes are review signals only. The four-hour ceiling is a stop condition.

7. Trust boundaries and data flow

Every external call crosses a named trust boundary. Every content item remains data. A response or memory cannot invoke a tool or change capture state.

Figure 4. Security boundaries and data classes. Local save approval, Lakebase sync approval and outbound-context approval are separate decisions.

8.1 Common operation states

Local submission uses NOT_SENT, SENDING, ACKNOWLEDGED and UNCERTAIN. Backend response states include pending, completed, incomplete, failed and cancellation requested. Unknown future states remain visible for diagnostics.

8.2 Common failure behavior

  • Permission denial prevents capture.
  • Provider timeout returns a marked fallback.
  • Uncertain submission prevents an automatic duplicate.
  • Workspace change creates a new conversation.
  • Stale callbacks cannot mutate a new route or MOG.
  • Offline memory sync uses idempotent retry.

10. Meeting recording policy

Recording stops on explicit or environmental signals. Time alone does not stop a healthy meeting at 60 or 90 minutes.

SignalRequired behavior
User selects StopStop new capture. Close the current journal segment. Preserve completed data.
60 minutes elapsedShow elapsed time. Continue recording.
15 minutes without speech on every active trackShow a 60-second countdown. Stop when it reaches zero. Reset it when speech resumes.
VAD unavailableDisable silence stopping and show that state. Keep manual stop and the hard ceiling.
90 minutes elapsedShow a review notice. Continue while meeting signals remain active.
Calendar endAsk whether to continue. Do not stop for this signal alone.
Trusted call provider reports microphone releaseStart a 30-second grace period. Stop if the state remains released.
Trusted call provider reports microphone ActiveCancel the release grace period. Continue recording under the other policies.
Call provider state is UnknownDo not use this signal. Keep the other stop policies active.
System sleepStop capture. Finalize safe segments. Mark the session interrupted. Do not resume automatically.
Free disk space reaches 2 GiBWarn the user. Continue above the stop threshold.
Free disk space reaches 500 MiBStop before the journal reserve is exhausted. Preserve completed segments.
Privacy indicator failsStop within one second. Preserve completed segments.
Four hours elapsedStop. Require a new explicit start for another session.

10.1 Meeting data rules

  • Use crash-safe segments and bounded transcription chunks.
  • Keep microphone and system tracks separate when supported.
  • Do not infer named speakers from track labels.
  • Delete raw audio after transcription unless meeting-audio retention is enabled.
  • Do not send meeting context automatically to Genie.
  • Require participant-notice and jurisdiction-specific legal review for managed deployment.

11. Data classes, retention and deletion

ClassExamplesRequired handling
SecretOAuth tokens, Lakebase credentials, encryption keysNative secret boundary only. Never enter webview, exports, logs or crash reports.
Sensitive contentAudio, transcripts, memory, questions, context, SQL, rows, responsesEncrypted local storage. Explicit transmission controls. No ordinary content logging.
Security metadataApproval ID, payload digest, target origin, request ID, deletion receiptEncrypted local storage. Allowlisted diagnostic fields.
Internal metadataProfile, workspace ID, MOG ID, backend ID, permission stateLimit disclosure. Redact unnecessary URL values in diagnostics.
PublicInstaller, documentation, nonsecret UI assetsSign executable artifacts. No confidentiality control is needed.

11.1 Retention classes

  • Transient: push-to-talk audio and temporary ASR buffers. Remove after transcription.
  • Session: meeting journals and partial recovery state. Apply the configured meeting retention period.
  • User content: raw and cleaned transcripts, approved memories and response references. Keep until their retention class expires or the user deletes them.
  • Derived content: embeddings and summaries. Keep the same sensitivity and retention as their source.
  • Tombstone: keep the minimum deletion metadata needed to prevent resurrection during sync.
Deletion limit: local deletion and acknowledged Lakebase deletion do not prove backup erasure or Genie conversation deletion. The UI must state what each service confirms.
